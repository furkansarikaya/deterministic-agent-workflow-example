# Enforcement matrix

"Script-enforced" means `scripts/agent.sh` (or `wiki-lint.sh`) fails closed; "policy-only" means only instructions stand behind it. Never describe policy-only behavior as technically disabled.

| Rule | Classification | Mechanism |
|---|---|---|
| Active task selection | Script-enforced | An empty checked-in `ACTIVE_RUN` reports `active_task=none`; malformed/missing targets fail and implementation commands require an explicit valid task. |
| Valid mode / effective policy | Script-enforced | `agent.sh effective` reads YAML only from the allowlisted mode directory. |
| Role command boundary | Script-enforced for CLI commands | Default `full_lifecycle` (Orchestrator) is agent-neutral and may run everything. `implementation_worker` cannot baseline/branch/freeze/refreeze/classify, cannot take later handoff phases, deliver, terminate or clean up. `independent_reviewer`, `independent_qa` and `independent_verifier` may run only `role`, `status`, `effective`, `pipeline`, `verify-*`, `freshness`, `validate`, `patch-fingerprint` and record their own gate type. `explorer` and `architect` may run the same read-only commands and record nothing. `AGENT_ROLE` is a declared claim (see "Evidence strength"). |
| Recursive delegation, swarm, more than one implementation worker, explorer count above the class bound | Policy-only | The repository has no agent-spawn interceptor; mode policy (`orchestration.swarm: false`, `recursive_delegation: false`, `max_implementation_workers: 1`), `pipelines.*.max_explorers`, role instructions and vibecosystem policy prohibit them. |
| Task, evidence, plan, QA plan, policy freeze | Script-enforced | SHA-256 values in `RUN.yaml`; an artifact the pipeline does not require is recorded `not_required`; `agent.sh verify-freeze` rejects mismatch. |
| Task classification selects the pipeline | Script-enforced (the *choice* of class is an orchestrator judgment against the documented criteria) | `agent.sh classify` (`full_lifecycle` only) records `pipeline.classification`/`review`; `freeze` refuses an unclassified run; `freeze.pipeline` records it so a later change fails `verify-freeze` until amendment + `refreeze`; the fields are in the ledger digest so a hand edit is detected. TRIVIAL is bounded mechanically (`max_scope_paths`). |
| Artifacts match the pipeline | Script-enforced | `freeze` requires `EVIDENCE.md`/`QA_PLAN.md` exactly when the class needs them and rejects them otherwise; COMPLEX/CRITICAL need an `## Architecture` section in `PLAN.md`; only pipeline-required run files are control metadata, so any other file (an unrequired report, scratch, notes) is an unexpected artifact — checked directly in the run directory (runs are gitignored, so git cannot see them) at every `verify-scope`, and therefore every handoff, gate and `validate`. |
| Planning freshness | Script-enforced for local Markdown/none sources | `agent.sh freshness` validates base SHA and the frozen task contract; unsupported external adapters block rather than invent state. |
| Handoff patch integrity | Script-enforced | `agent.sh verify-handoff` invalidates IMPLEMENTED/CODE_DONE evidence when the task-owned patch fingerprint changes. |
| Delivery boundary | Script-enforced local gate | `agent.sh delivery-check` never mutates a remote; it requires current freshness, application-scope and knowledge-transaction integrity, and current IMPLEMENTED/CODE_DONE fingerprints with every required gate. See `.agents/WORKFLOW.md`'s "Knowledge transaction scope". |
| Application scope and AC mapping | Script-enforced | `agent.sh verify-scope` validates task-introduced application paths against PLAN mappings. |
| Dirty-worktree baseline | Script-enforced | `agent.sh baseline` stores `repository.base_sha` and regular-file SHA-256 fingerprints. An unchanged user-owned dirty file is excluded; a later change is checked against scope. |
| Deterministic task branch isolation | Script-enforced for a run whose `RUN.yaml` declares `repository.task_branch` (the template does) | `agent.sh branch` creates `task/<TASK-ID>-<slug>` from the canonical branch's exact tip (`canonical_branch` in `.agents/config.yaml`) and records it; `baseline`, `freeze`/`refreeze`, `handoff`, `verify-scope` and `delivery-check` fail closed unless the working tree is on that branch. `implementation_worker` cannot call `branch`. |
| Never overwrite/delete a conflicting branch | Script-enforced | `agent.sh branch` refuses to reuse a same-named branch whose tip differs from the canonical base, and never runs `git reset`/`git clean`/a force checkout/branch delete; an unsafe switch is left to Git's own refusal. |
| Required run artifacts | Script-enforced | `agent.sh validate`, runnable at any phase: TASK, PLAN, RUN.yaml, the pipeline's EVIDENCE/QA_PLAN, the completion report, a clean control-artifact set, a captured baseline, freshness, scope (application + knowledge) and handoff integrity. |
| Build/tests/static checks | Script-enforced | `scripts/verify.sh` and the Verifier's `VERIFY.md` + VERIFY gate. |
| Wiki structural integrity | Script-enforced | `wiki-lint.sh` reports, never rewrites; every whole-vault scan excludes its own generated `lint-report.md` by name. It does not depend on any run directory. Regression: `wiki_lint_self_scan_test`. |
| Progressive context loading | Policy-only | Mode YAML and shared rules require on-demand retrieval, but repository scripts cannot observe an agent's context window. |
| One implementation worker / separate reviewer, QA and verifier | Script-enforced for the gates, policy-only for headcount | Distinct gate records and reports per role, with author-role checks; platform identity and process count are unavailable to this repository. |
| Wiki no-write during code transaction | Policy-only | Repository scripts can detect scope after the fact but cannot intercept editor writes. |
| Memory, recall, prompt improver, learning writes, swarm | Policy-only | Deterministic policy denies them; installed host hooks/profile selection remain host-controlled. |
| Credential denial | Platform-enforced when the vibecosystem core hook is active | Actual `credential-deny` core hook; the repository does not assume it is installed. |
| User confirmation for destructive/external actions | Agent/platform policy | Documents require it; scripts do not authorize actions. |
| Execution topology resolution | Script-enforced, fails closed | `resolve_topology` (in `scripts/agent.sh`) reads `execution.topology` or `default_topology`; invalid on both is a hard failure. |
| Implementation evidence required to leave IMPLEMENT | Script-enforced for a run with `worker_evidence:` (the template does), both topologies | `agent.sh handoff <ID> IMPLEMENTED` calls `verify_worker_evidence`: every non-exempt frozen scope path needs valid RED+GREEN/FIX evidence bound to the current frozen hashes and authored by the role `expected_implementation_owner` resolves for the topology. |
| Implementation-evidence structure / task / freeze / role binding | Script-enforced | `agent.sh worker-evidence` accepts only the topology's expected role, refuses out-of-scope targets, a `RED` without `result: fail` and a specific `expected_failure`, and a non-RED without `result: pass`; `verify_worker_evidence` rejects files whose task, hashes or role no longer match. |
| Implementation-owner identity proof | Declared, optionally cross-checked | `AGENT_ROLE` is a declared claim in both directions. When a local Codex session log directory is discoverable, a recorded `codex_session_id` is cross-checked; this narrows but does not close the gap. |
| TDD exemption validity | Script-enforced (structural) | An empty, too-short (< 20 chars) or stock-phrase `tdd_exemption` in `PLAN.md` is rejected. Whether a valid-looking exemption is appropriate is a Reviewer judgment recorded in `REVIEW.md`. |
| Task Completion Report required before DONE | Script-enforced for a run with `completion_report:` (the template does) | `handoff DONE` fails unless the report is published, `knowledge_state` is `KNOWLEDGE_DONE`/`not_applicable`, and `verify-completion-report` (which re-invokes the adapter's `verify`) passes. Required sections follow the pipeline (`## Review Result`/`## QA Result` only when those gates ran). |
| Task-integration adapter boundary | Script-enforced structure, policy-only content | `agent.sh` validates the report's section structure and delegates `publish`/`verify` to `.agents/task-integrations/<name>.sh`; it encodes no tracker API. |
| Canonical worker invocation path (orchestrated only) | Script-enforced fail-closed, no fallback | `scripts/worker-run.sh` is this repository's one `implementation_worker` adapter (Codex). A missing `codex` or a non-zero exit is a hard failure with a preserved log, never a silent `full_lifecycle` fallback; it refuses a `standalone` run; its sandbox grant is a single `--add-dir` for the run's own `worker-evidence/`. Model/effort come from the operator's `~/.codex/config.toml` unless passed explicitly. |
| Worker evidence write is fail-closed | Script-enforced | `worker-evidence` verifies its write produced a non-empty, well-formed file, else removes it and aborts. Regression: `worker_evidence_write_failure_test`. |
| Knowledge transaction (Transaction B) scope | Script-enforced, fails closed | `knowledge_scope_root` is the sole allowlisted prefix for post-CODE_DONE wiki writes; `verify-knowledge-scope` requires every changed path under it to coincide with `knowledge_state = KNOWLEDGE_DONE`, rejects a diff without a recorded transaction, and rejects `KNOWLEDGE_DONE` with zero diffs. A path outside the root is always application scope. |
| DONE, delivery-check and validate need application-scope and knowledge-scope integrity | Script-enforced | `handoff DONE` checks `code_done_patch_sha256` and `verify-knowledge-scope` independently; `delivery_check` and `validate_run` mirror it (`verify_scope "$id" 1` + `verify_knowledge_scope` + `verify_handoff "$id" 1`). Every earlier phase and the `verify-scope`/`verify-handoff` commands stay strict. Regression: `knowledge_scope_test`, `delivery_check_knowledge_scope_test`, `validate_knowledge_scope_test`. |
| REVIEW, QA and VERIFY gates bound to the exact final tree and the role's report | Script-enforced for a run with `lifecycle_gates:` (the template does) | `agent.sh gate` appends records with the patch fingerprint, frozen hashes (incl. the QA plan) and the hash of `REVIEW.md`/`QA_REPORT.md`/`VERIFY.md`, which must exist with a matching `Verdict:` line. `CODE_DONE`/`DONE`/`delivery-check`/`validate`/`verify-handoff` require a current pass for every gate the pipeline lists, in any order. A changed tree, an edited report or a later fail voids the pass. A gate outside the pipeline is refused. |
| Independent review / QA / verification | Script-enforced role check; identity is a declared claim | With `review.independent`, `qa.independent`, `verification.independent_verifier` true, a pass is accepted only from `independent_reviewer`/`independent_qa`/`independent_verifier`; a `full_lifecycle` self-authored pass is rejected at record time and at every later transition (a hand-relabelled record too). With a flag false `full_lifecycle` may author that gate. Whether two agents are actually independent processes is not provable by a script. |
| Gate findings are a bounded fix contract | Script-enforced | A failing gate requires `findings`, `fix_instruction` and frozen-scope `fix_scope`; the tree is then an open finding. The only way back is `handoff IMPLEMENTING`, at most `max_bounded_fix_attempts` (default 2) times per frozen contract (task, evidence, plan and QA plan hashes) across all gates; returning to `IMPLEMENTED` requires a changed tree whose changed paths are all inside `fix_scope` (entries trimmed of surrounding whitespace). Exhaustion is escalated by an explicit amendment + `refreeze` that changes a frozen artifact (fresh budget) or ended by `terminate`. |
| Terminal outcomes | Script-enforced | `agent.sh terminate <ID> FAILED|BLOCKED` (`full_lifecycle`; specific reason and evidence): `FAILED` only after the fix budget is exhausted, `BLOCKED` for an outside blocker. The state is ledgered and terminal — handoff, gate, classify, freeze, worker-evidence, window, knowledge-done and amend all refuse it. |
| Runtime artifacts are disposable | Script-enforced | `agent.sh cleanup <ID>` (`full_lifecycle`) requires handoff DONE, re-verifies handoff integrity and the published report (or a terminal FAILED/BLOCKED run), requires a ledgered `terminate` as the last transition for a FAILED/BLOCKED run (a hand-set state is refused), deletes only `.agents/runs/<ID>/` (a plain directory directly under `runs/`) and clears `ACTIVE_RUN` if it names the run. `.agents/runs/` is gitignored. Cleanup is invoked by the Orchestrator; a script cannot force it. |
| Application/test mutation ownership under `orchestrated`, for the whole lifecycle | Script-enforced detection at every gate (not write-time prevention) | `worker-run.sh` brackets each worker run with `window-open`/`window-close`; windows must chain and the current tree must equal the last window's end at IMPLEMENTED, CODE_DONE, DONE, every gate, `validate`, `delivery-check`, `verify-handoff`. An orchestrator edit to application/test files is rejected. Not applied under `standalone`. Residual: a forged window or a declared role is not cryptographically stopped; blocking the editor at write time is a host concern. |
| Lifecycle ledger / manual state rewind | Script-enforced detection | `LEDGER.log` is a hash chain of every control-plane transition sealing a digest of `execution.state`/`knowledge_state`, `handoff.*`, `pipeline.*`, `completion_report.*` and the task source path/revision. A hand edit of those fields or the ledger fails `handoff`, `gate`, `classify`, `terminate`, `knowledge-done`, `publish-completion-report`, `freeze`, `validate`, `verify-handoff`, `delivery-check` and `verify-seal`. A same-user actor who rewrites RUN.yaml and re-seals the ledger is not stopped. |
| Reopening CODE_DONE/DONE | Script-enforced | `agent.sh amend <ID>` (`full_lifecycle`; reason, fix_scope, fix_instruction, authorized_by) is the only reopen: fail-closed, records who/why and the prior completion state in `gates/NNN-REOPEN.yaml`, voids gates and the published report, keeps frozen artifacts, needs `refreeze` with an amendment file for a plan change, and requires a `## Reopen History` section in the new report. Needs freshness, so it precedes the delivery commit and cleanup. |
| Task source status agrees with its lifecycle folder | Script-enforced for a local Markdown task source in `backlog/`, `todo/`, `in-progress/` or `done/` | `freeze`, `refreeze` and `freshness` (hence `handoff`, `gate`, `knowledge-done`, `delivery-check`, `validate`) refuse a `**Status:**` value that contradicts the folder. `task-source-status <ID>` (`full_lifecycle` only, ledgered) rewrites only that line, refuses when the frozen contract would change or once the report is published, and a Status-only change is not scope drift (`verify-scope`). |
| Frozen task contract is never silently re-baselined | Script-enforced for a local Markdown task source | `task_source.revision` hashes a projection (Status value and the published report block excluded) written only by `freeze`/`refreeze`. `publish-completion-report` checks freshness before and after the adapter (in a separate process), restores the task source byte for byte and records nothing if the adapter changed anything outside its block. `knowledge-done`, `handoff`, `gate`, `delivery-check` and `validate` reject a changed contract. |
| Task-source location and revision are sealed; relocation is explicit | Script-enforced | `path` and `revision` are in the ledger digest. `agent.sh task-source-relocate` (`full_lifecycle` only) is the only move: the contract at the new path must hash to the frozen revision, the old path must be gone, it is refused after the report is published, and it is ledgered. Regression: `lifecycle-test.sh` `scenario_task_contract_*`. |

## Evidence strength

Hashes, policy selection, `repository.base_sha`, baseline fingerprints, ledger chains and gate/report bindings are machine-verifiable. Worker roles, worker identity, and the independence of reviewer, QA and verifier are declared workflow evidence unless the host platform supplies auditable identities. Baseline hashes prove that a file changed after task start, not that an authorized edit semantically preserved every part of user-owned work; reconciliation remains an agent and review obligation.

Which enforcement layers apply to a run is decided by the policy keys in its `RUN.yaml` (`worker_evidence`, `tdd`, `completion_report`, `lifecycle_gates`, `repository.task_branch`); the run template carries them all, and only the isolated fixture suites in `agent.sh test` omit some to test one layer at a time. The ledger seals lifecycle fields, not the presence of those keys, so a same-user actor who deletes a key from `RUN.yaml` is not stopped — the same declared-claim limit as above.
